# 维护手册 · 新参考脚本入库 SOP

当 Craig 发来新的视频转录稿/脚本参考并要求"更新进 skill"时,严格走以下流程。目标:**原料永久保存 + 提炼可追溯 + 范文可校准**,绝不允许"提炼完丢原料"。

## 入库五步

1. **清洗**:按 `errata.md`(听写错字勘误表)做专名替换;新发现的高置信错字**追加进勘误表**(错写|正确 格式)。保留全部语气词(哈/呢/啊)——语气词是语域本体,不许修通顺。
2. **归档**:全文存入 `corpus/`。已有作者→追加到该作者文件;新作者→新建 `{风格字母}-{拼音}.md`(文件名一律 ASCII,中文写在文件内头部),头部注明作者、条数、清洗状态。
3. **判型**:判断该作者/该批稿件属于既有 A–H 哪个风格,还是新风格。
   - 既有风格的新素材 → 对照该 style 文件,把**新出现的**句式/手法增补进去(已覆盖的不重复);
   - 疑似新风格 → 先提炼骨架+hook库+语气标记,新建 style 文件或作为某 style 的变体,并更新 SKILL.md 的矩阵映射。
4. **选范文**:若新作者数据/典型性优于现有范文,或填补了某格子空缺 → 按 `exemplars/README.md` 的格式(元信息+清洗全文+`>> [拍点]` 标注)制作范文入库,更新 README 清单。每个风格保持 1-2 篇,贵精不贵多。
5. **同步**:更新 SKILL.md 受影响的部分(矩阵映射/风格清单);提醒 Craig 重新打包 `.skill` 或 push 到 GitHub 记忆仓库,防止环境重置丢失。

## 红线

- corpus 只进不出:旧语料即使不再用作范文,也不删除。
- 勘误表是活文档:每批新听写稿的错字都要回写。
- 范文必须带拍点标注:没有 `>> [拍点]` 的全文不算范文,只能进 corpus。
- 软广剔除:按 toolbox 第七节的软广识别清单过滤,被剔除的在 corpus 头部注明,不做风格提炼依据。
